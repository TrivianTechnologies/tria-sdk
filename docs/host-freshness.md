# Host-managed freshness and receiver admission v1

This opt-in Linux/file-SQLite profile implements part of Zixuan Guo's Week 8 and Week 9 work on delegated authority. It has one canonical data host. Independent receiver processes can accept network requests but serialize their admission against that host’s authoritative SQLite database. The protected effect is exactly one durable digest inbox entry. External transfers, callbacks and work later taken from the inbox each need their own enforcement.

## Commit semantics

A grant or revocation becomes authoritative when the ordinary TRIA event-store transaction commits. The signer opens a fresh read transaction on that same database for every challenge. It verifies the relationship history, locates the material source event and compares the host’s independently published evidence. A completed revocation is immediately visible to subsequent reads. A challenge answered from a read ordered before a concurrent revocation describes that earlier snapshot. It is never consumable as authority.

The primary allocates a source revision using the actual SQLite commit index and binds it to the material event ID and event hash. Five named governance/invocation audit records are transparent to the material fence. All other events advance it, including unknown event types. Changes to how those five events affect projection or authority require a profile review. A local replica’s length or projection cursor cannot substitute for the enrolled authoritative source. The separate evidence-publication journal appends a content hash under a compare-and-swap on both the observed material head and prior publication. Superseded known evidence is stale. Never-published evidence is unverified. A signer cannot silently rebind an old publication to a new source head.

The value of expected in publish must be captured when the host obtains the evidence. Under this profile the authoritative commit of a policy/evidence publication is the primary publication transaction. If another system owns an earlier effective policy transition, integrate that system into the commit order or return unverified. Content provenance and truthful independent collection remain host responsibilities.

## Integration

1. Provision a canonical file-backed SQLiteEventStore, a governed Relationship, an Ed25519 key, a Domain and a trusted genesis event hash. The domain binds issuer, epoch, relationship and receiver scope. Protect the path, backing disk, key, clock, process identity and database permissions. Call Authority(relationship,domain,key,genesis,enroll=True) once. Reopen with enroll omitted. Hot key/epoch swaps are refused.
2. Capture authority.cursor() when independently obtaining the scoped policy/evidence. Publish the corresponding subject digest with authority.publish(subject,expected=cursor). Supply authority.answer as the signed online observation exchange for an independently enrolled verifier. All read and write connections target the same database. Exported snapshots and lagging read replicas are inappropriate enrollment targets.
3. A trusted API handler authenticates the caller and constructs a fully scoped InvocationRequest. Include ACT on the exact target, applicable capability and consent requirements, and a stable operation ID. Call authority.offer(request,subject,ttl_ms=5000). This calls the existing ExecutionBridge on the authoritative relationship and stages only a request digest. No client receives private context or an executable credential. Externally asserted satisfied conditions and external context resolvers require a different live validation profile and are rejected here.
4. An independently hosted receiver endpoint on the data host opens Receiver(path,domain,public_key,genesis). It admits the exact request under BEGIN IMMEDIATE. It checks enrollment, the trusted root, source and publication fences, the durable offer, the operation digest and current TRIA governance. It checks a short offer lifetime on a suspend-aware boot clock. The insert and commit create the effect. A committed admission linearizes at the final protected check in that transaction. Other writers, including ordinary event appends, must wait. Already-admitted responses report a historical receipt. They do not grant a second effect.
5. After timeout or lost reply, reconcile by retrying the same request with the same stable ID. An unconfirmed storage outcome can include an already committed row. Reuse with different contents conflicts. An expired or fenced offer needs a newly authorized operation. Never automatically retry under a new ID after an unknown outcome.

## Failure, trust and recovery

- A partition before receipt creates no admission. A delayed message arriving after a material change is fenced. Independent receivers share the unique admission key. Crash/reopen against the intact primary recovers the offer and effect journal. A reboot invalidates old offers. Existing durable admissions remain reconcilable.
- The source material index and separate publication generation advance independently. The issuer verifies membership of both parts of a verifier's floor. The verifier detects signed regressions or contradictions against its durable checkpoint. Neither history length nor a signed wall-clock timestamp establishes currency.
- UTC must be trustworthy for the SDK’s existing consent/grant-expiry rules. The additional offer timeout uses Linux CLOCK_BOOTTIME and boot ID. On unsupported platforms use the existing SDK API without claiming this profile.
- Concurrent processes share only the opt-in tables for writes outside the existing SDK owner. The receiver reads and verifies an immutable snapshot of the source event chain inside its transaction and uses the native Runtime.evaluate. It never appends TRIA events or runs a provider. Direct event writers, custom stores, custom governance engines and hostile Python callers are outside this profile.
- Protect source and verifier durability separately. Restoring an entire authority disk to an old state can resurrect both an old offer and old governance. Stop admission before restore, retire the old epoch and endpoints, reconcile effects and independently re-enroll from a verified authoritative history. No automatic failover, split-brain detection across unseen primaries, safe asynchronous replication or consensus is supplied.
- Install only on a supported local filesystem with reliable SQLite locking and durability. The network test uses real loopback sockets and independent receiver processes. Separate machines with independent writable databases or network-mounted SQLite are outside this guarantee. A remote irreversible effect needs an equivalent ordering primitive at its last point of control. Revocation cannot cancel work already admitted.
- All history reads currently verify the complete relationship log. Bound admission load and manage storage. Retain offer/inbox deduplication records for the full retry horizon. Production key management, TLS/caller authentication, rate limits, retention, and heavy-load validation belong to the host.

The unchanged base APIs retain their documented semantics. The optional freshness extra supplies the exact draft shared observation contract. Use tests/test_freshness_host.py and tests/test_freshness_receiver.py for reproducible adoption examples.
